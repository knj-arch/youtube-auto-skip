  attribute.repository_id=assertion.repository_id

생기지는 않습니다. 공식 안내의 게시자당 연결 가능한 서비스 계정 제한도 확인합니다.

3. 참고용 대체 방식: Google OAuth refresh token (현재 사용하지 않음)

현재는 위 WIF 연결로 실행하므로 아래 개인 OAuth 설정은 사용하지 않습니다.
코드는 WIF 변수 두 개를 모두 비워 둔 경우에만 아래 OAuth 방식을 지원합니다.
WIF를 구성했다면 OAuth Secrets가 존재하더라도 인증 실패를 OAuth로 우회하지 않습니다.

Google Cloud 프로젝트에서 Chrome Web Store API를 사용 설정합니다.
Google Auth Platform에서 OAuth 동의 화면을 구성하고 External로 본인 계정을
허용합니다. Credentials에서 Web application OAuth client를 만듭니다.
Authorized redirect URI에 https://developers.google.com/oauthplayground 를 추가합니다.

OAuth Playground를 열고 설정에서 Use your own OAuth credentials를 켠 뒤
생성한 Client ID와 Client secret을 넣습니다.
Input your own scopes에 아래 범위 하나를 입력합니다.
https://www.googleapis.com/auth/chromewebstore

Authorize APIs에서 이 스토어 항목을 소유/관리하는 Google 계정으로 로그인하고,
Exchange authorization code for tokens로 refresh token을 발급받습니다.
Playground 설정의 Access type은 Offline을 사용합니다.
OAuth 동의 화면이 External + Testing이면 refresh token은 7일 후 만료됩니다.
지속 자동화에는 In production으로 전환하고 필요 검증을 마친 뒤 토큰을 다시
발급하세요. 운영 상태에서도 사용자 권한 취소 등으로 토큰이 무효화될 수 있습니다.
토큰은 GitHub Secrets에 직접 저장하고 코드나 채팅에 붙여 넣지 않습니다.

OAuth 공식 안내: https://developers.google.com/identity/protocols/oauth2#expiration
Playground: https://developers.google.com/oauthplayground

4. GitHub 저장소 설정

저장소 Settings → Secrets and variables → Actions에 아래 값을 추가합니다.
현재 저장소에는 공통 2개와 WIF 2개, 총 4개 Variables를 실제 설정했습니다.

공통 Variables:
  CWS_PUBLISHER_ID    1c3467ca-1ed5-46e9-b508-4f6bc1e03a60
  CWS_EXTENSION_ID    oilfjmphaeclhghjdiflbolddhdokimh

WIF 방식의 추가 Variables:
  CWS_WORKLOAD_IDENTITY_PROVIDER    projects/201518632423/locations/global/workloadIdentityPools/github-actions/providers/github-main
  CWS_SERVICE_ACCOUNT_EMAIL        github-cws-publisher@knj-youtube-auto-skip-cws.iam.gserviceaccount.com

WIF 방식에는 아래 OAuth Secrets 세 개가 필요하지 않습니다. CWS_ACCESS_TOKEN은
auth 액션의 access_token 출력을 해당 실행의 환경변수로 전달하며, 고정된
GitHub Secret이나 Variable로 저장하지 않습니다. 단기 토큰은 일반 로그·오류에서
가려지며 GitHub의 add-mask 명령으로도 마스킹합니다.

OAuth fallback 방식에만 필요한 Secrets:
  CWS_CLIENT_ID       OAuth Client ID
  CWS_CLIENT_SECRET   OAuth Client secret
  CWS_REFRESH_TOKEN   스토어 계정으로 받은 refresh token

공통 Variables 두 개가 없으면 ZIP만 생성하고 스토어 제출을 건너뜁니다.
공통 Variables가 있으면 WIF 또는 OAuth 인증을 검사합니다. WIF 변수 중 하나만
설정한 경우에는 명확한 오류로 중단합니다. WIF 변수 두 개가 모두 있지만 단기
토큰을 받지 못한 경우에도 OAuth로 우회하지 않습니다. OAuth 모드에서 Secrets가
빠졌으면 누락된 키 이름만 표시하며 제출 작업이 실패합니다.

5. 변경을 push하기

기존처럼 코드를 고치고 main에 push합니다. Actions의
Extension package and store submission에서 ZIP과 제출 결과를 확인하세요.
Actions 실행본에서만 manifest.version에 실행 번호가 붙습니다.
이번 제출: 소스 1.0.5 + workflow run number 8 → 스토어 버전 1.0.5.8
로컬 소스 manifest와 Git 기록은 자동 버전 처리로 바뀌지 않습니다.
확장 코드/아이콘/패키징/배포 스크립트 변경이 이 워크플로를 실행합니다.
README나 개인정보 페이지 변경은 스토어 버전을 새로 제출하지 않습니다.
필요하면 Actions의 Run workflow를 main에서 실행할 수 있습니다.
상태만 확인하려면 별도 Chrome Web Store status 워크플로를 수동 실행합니다.
그 워크플로는 버전을 올리거나 업로드·심사 제출하지 않습니다.
큰 릴리스 때는 소스의 앞 3자리 버전을 직접 올립니다.
실행 번호가 65535에 도달하기 전 기본 버전을 올리고 새 워크플로 이름으로
실행 번호를 다시 시작해야 합니다(파일 이름 변경 필요).

6. 심사와 실패 재시도

업로드의 비동기 검증은 최대 5분까지 확인하고 성공한 경우에만 심사 제출합니다.
다른 버전이 이미 심사 중/게시 대기면 그 결과를 기다리고 실패한 실행을 재실행합니다.
같은 실행을 재실행하면 같은 버전이고, 이미 게시/심사 제출된 버전은 건너뜁니다.
업로드 완료 후 심사 요청만 실패한 경우에는 해당 실행의 비밀정보 없는 업로드
receipt artifact를 복원하여 심사 제출만 재시도합니다(30일 보관).
업로드 중 네트워크 오류나 시간 초과로 완료 여부가 불명확하면 대시보드 상태를
먼저 확인하세요. receipt가 없거나 만료되었다면 직접 심사 제출하거나 새 실행을 만듭니다.
워크플로는 이전 심사를 취소하거나 자동으로 교체하지 않습니다.
GitHub의 동시 실행 설정은 진행 중인 업로드를 중단하지 않지만 빠르게 연속된
push는 대기 실행이 최신 실행으로 대체될 수 있으므로 최신 코드가 제출됩니다.
invalid_grant 오류는 OAuth 상태를 확인하고 refresh token을 다시 받아 교체합니다.
WIF 인증 오류는 provider의 issuer·숫자 저장소 ID·owner ID·main 조건,
서비스 계정의 workloadIdentityUser 바인딩과 스토어 대시보드의 서비스 계정
연결을 각각 확인합니다. 새 IAM 설정의 전파에는 시간이 걸릴 수 있습니다.
만료된 단기 토큰은 저장해서 재사용하지 않고 새 Actions 실행에서 다시 발급합니다.
공개 범위 변경이나 스토어 자료 누락은 대시보드에서 수정해야 합니다.
